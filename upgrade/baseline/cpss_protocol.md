# CPSS head-to-head baseline — PROTOCOL (fixed before any run)

Paper 8: "A Type-Aware Bottom-Up Discovery Pipeline for Cross-Domain
Enterprise KPIs with Spurious-Correlation Filtering" (target: Knowledge
and Information Systems). This protocol was written and saved before any
CPSS computation was run. It fixes every design choice below; any
deviation discovered during implementation is to be recorded in
`baseline_report.md`, not silently absorbed.

## 1. Purpose

The manuscript already contains a φ_K variant-pipeline cross-check
(probe 6) but no head-to-head against a published stability-selection
procedure. This baseline supplies that comparison against
**complementary-pairs stability selection (CPSS)** — Shah & Samworth
(2013), building on the stability selection of Meinshausen & Bühlmann
(2010) — adapted to this pipeline's pair-mining selection problem.

No claim is made that the Shah–Samworth error-control bound applies
here: that bound is proved for a variable-selection procedure with a
fixed per-subsample selection set size and (r-concave) simultaneous
control conditions that a pairwise strength-threshold rule does not
satisfy. This is an *empirical* head-to-head of selection rules on
identical data, identical branch statistics and identical families.

## 2. Selection event (identical for every rule that uses resampling)

For an ordered pair of columns (X, Y) and a row set S, the selection
event on S is

    corrected strength of (X, Y) computed on S  ≥  τ,   τ = 0.20,

where "corrected strength" is exactly the branch statistic of
`hidden_files/paper08_work/probes/facade_v2.py`:

- numeric–numeric: |Pearson r| (facade reports no separate corrected
  value for this branch; corrected := strength, compared in absolute
  value);
- categorical–categorical: Bergsma (2013) bias-corrected Cramér's V*
  (`strength_corrected`), computed on the contingency table of the
  levels *observed in S* (matching `facade_v2.correlate`, whose
  `pd.crosstab` drops unobserved levels);
- numeric–categorical (either order): max(ω², 0), Hays' omega-squared
  (`strength_corrected`), with groups = levels observed in S after
  dropping rows whose numeric value is missing.

Missing values are handled pairwise, exactly as the facade does
(Pearson: rows finite in both; ω²: numeric non-missing; V*: rows
non-missing in both).

## 3. CPSS design

- Draw B complementary subsample *pairs*. Each pair is one random
  permutation of the n row indices, split into a first half of size
  ⌊n/2⌋ and its complement (size n − ⌊n/2⌋). **Both** halves are
  evaluated, giving 2B selection evaluations per pair of columns.
- Subsample index sets are drawn at the *dataset* level (one
  permutation per complementary pair, shared by every column pair in
  the family), as in the original CPSS formulation where a subsample
  is a subsample of observations, not of variables.
- The stability frequency of a column pair is
  Π = (number of the 2B halves on which the selection event occurs) / 2B.
- **Field runs: B = 100** (200 evaluations per column pair).
- **Synthetic runs: B = 50** (100 evaluations per column pair) per
  world — a declared compute reduction (16+ worlds × up to 1326 pairs);
  the field design value B = 100 is unchanged.
- Random seeds (fixed here): synthetic world generation exactly as
  probe 2 (`RandomState(31000 + w)`); synthetic CPSS permutations
  `RandomState(91000 + w)` per world w; field CPSS permutations
  Olist `RandomState(20261101)`, Telco `RandomState(20261102)`
  (the Olist text-pair family on the commented subset uses
  `RandomState(20261103)` on that subset's rows).

## 4. Rules compared (four, everywhere)

1. **Paper conjoint (P1∧P2∧P3)** — the manuscript's promotion rule,
   exactly as in probes 5/7:
   P1: Benjamini–Hochberg rejection at q = 0.05 over the family's
   full-sample facade p-values; P2: full-sample corrected strength
   ≥ 0.20; P3: split-half reproducibility — the fixed
   `RandomState(7)` permutation of the pair's rows, corrected strength
   ≥ 0.20 on *each* disjoint half. Evaluated only on P1∧P2 survivors,
   as in the probes (the resulting set is identical to evaluating P3
   on all pairs and intersecting).
2. **CPSS π = 0.90 (primary baseline rule)**: Π ≥ 0.90. No BH, no
   separate full-sample floor. π = 0.90 is the pre-chosen primary
   threshold.
3. **CPSS π = 0.80 (declared sensitivity)**: Π ≥ 0.80. A sensitivity
   analysis, not a substitute for the primary rule.
4. **Hybrid (declared sensitivity)**: Π ≥ 0.90 (the primary π) ∧
   full-sample BH rejection at q = 0.05. No split-half, no separate
   floor condition.

## 5. Synthetic design (probe 2, verbatim)

Worlds generated by the functions in
`hidden_files/paper08_work/probes/probe2_fdr.py` (`base_columns`,
`planted_columns`), n = 500 rows:

- **Null worlds**: 40 independent columns (24 numeric, 8 cat-3,
  8 cat-2); all C(40,2) = 780 pairs are null.
- **Planted worlds**: `planted_columns` adds 6 planted pairs
  (ρ = .50 / .35 numeric; η² = .25 / .10 numeric–categorical;
  V = .45 / .25 categorical) to the same 40 base columns. (Note, to be
  verified against the code at run time and reported honestly: the
  probe-2 docstring says "46 columns / 1029 other pairs"; the code as
  written will be executed verbatim and the *actual* column/pair
  counts it produces are what this baseline reports.)
- **Worlds: 10 null + 10 planted** (requirement: ≥ 8 each).
- Per rule and condition, report: mean discoveries; in null worlds
  additionally mean false discoveries (identically the discoveries)
  and FWER = fraction of worlds with ≥ 1 discovery; in planted worlds
  additionally mean false discoveries, power = mean fraction of the 6
  planted pairs discovered, and mean realised FDP, where a world's
  FDP = (false discoveries) / max(discoveries, 1) (so FDP = 0 when a
  rule discovers nothing, the probe-2 convention).

## 6. Field design (probes 5 and 7, verbatim constructions)

- **Olist**: analysis table rebuilt exactly as in
  `probe5_olist_run.py` — delivered orders only, same joins and
  derived columns, 25,000 sampled orders (`random_state=20261027`),
  same control columns (`rand_num` from `RandomState(20261027)`,
  `review_score_perm` from `RandomState(1)`). Family = the
  pre-registered 107 pairs (105 column pairs over 11 numeric + 4
  categorical columns, plus the 2 TF-IDF text pairs on the commented
  subset, n = 9,378, TF-IDF + k-means seed 42 exactly as probe 5).
  The paper's promoted set for overlap comparison is probe 5's 13.
  Text pairs: CPSS permutations are drawn on the commented subset's
  rows; the derived `text_tfidf` column is held fixed (it is a column
  of the analysis table, as in probe 5's split-half).
- **Telco**: table exactly as in `probe7_telco_run.py` (7,043 rows;
  `TotalCharges` coerced numeric; controls `rand_num` from
  `RandomState(20261027)`, `monthly_perm` from `RandomState(1)`).
  Family = all 231 pairs over 5 numeric + 17 categorical columns.
  The paper's promoted set for overlap comparison is probe 7's 88.
- Per dataset and per rule, report: promoted count; overlap with the
  paper's promoted set; control-pair outcomes (number of control
  pairs in the family — pairs touching a control column — and how
  many each rule promotes, named if any); and the pairs each rule
  promotes that the paper's rule does not, named, with full-sample
  corrected strength and stability frequency Π (and the reverse
  direction, paper-promoted pairs a rule misses, named likewise).

## 7. Optimised engine and its validation gate

CPSS needs up to 200 strength evaluations per pair, so an optimised
numpy/scipy engine (`cpss_engine.py`, integer-coded categoricals,
bincount contingency / group sums) replaces the pandas facade inside
the resampling loops. The facade remains the reference for all
full-sample strengths, all p-values, BH, and the paper rule's P3.

**Gate**: before any CPSS number is trusted, the engine is validated
against `facade_v2.correlate` on ≥ 30 random pairs spanning all three
branches (≥ 10 per branch), each compared on the full sample *and* on
a random half-sample (the CPSS regime). Max absolute differences in
corrected strength are recorded in `engine_validation.json`.
Acceptance criterion, fixed here: max abs difference < 1e-6 on every
branch. If the gate fails, the engine is fixed and re-validated; no
run proceeds on a failed gate.
